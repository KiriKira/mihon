# 移动端大跨页识别：可审查算法与接入规格

**状态：修订中（修订 C）；分类器未实现，只有无模型证据探针为实验代码。不是效果或性能承诺。**

- 文档基线：`KiriKira/mihon` `042f8904b28fbef6f6e2f6934a01ea8da2a8fe4a`，已包含 #17 的修复；初稿基于 `7cc281df545f3a7da7a6757edd7c3a0b687efa90`。
- 交付范围：本文仍是设计文档，不替换现有检测器、不修改开关或阅读器；独立实验分支 [#18](https://github.com/KiriKira/mihon/pull/18) 新增一个不接线的无模型探针。
- 本方案由主助手负责算法与架构设计。辅助代理只允许核验代码、资料与事实，不负责设计取舍。
- 文中「初始值」用于实现可复现原型，**不是已经调优的参数**；「预算/发布门槛」是待真机和真实图源验证的目标。

## 1. 决策摘要（修订 C）

**首版不再实现「对所有宽图运行完整视觉管线」的整体替换。** 初始方案在没有任何标注数据时写得过宽：特征、分类器、接入服务和模型权重同时设计，而其中最贵的部分恰恰没有被证明有增益。

修订后的路线是：

1. **先冻结行为基线。** 以当前已发布路径（legacy + 当前增强，含 #17）为对照，不假设 raw legacy 就是今天的用户行为。
2. **先交付可重复的特征测量，不交付分类器。** 无模型探针已在 #18 实现：纯 Kotlin、512 上限、无解码/IO/依赖、无 `isSpread` 之类输出。
3. **区分两个目标：** ①减少真跨页被拆坏；②让普通双页更多被正确切开。二者分开报告，不能用一个“准确率”混合。
4. **首版默认保持 veto-only。** 它确实锁住目标②的召回上限，但目标①可以继续改进。是否突破门槛属于目标②的独立提案，必须由数据证明。
5. 只有分组真实数据上的消融显示某类特征有增益，才把对应特征提升到生产决策；**权重和阈值只能在数据到位后导出**。
6. 模型不可用、格式不支持或运行失败时，回退**相同设置下的当前完整路径**，包括当前增强的否决；不是绕过它只取 raw legacy。
7. 只在有实测依据时引入缓存、single-flight 和显示计划重建；#17 已用较小改动修复已证实的 InsertPage 残留，无需以此为由重做架构。

**为什么不直接上 CNN：** 缺的是带难负例、按作品/扫描来源隔离的验证集，不是模型容量。但也**不能反过来假定手工特征一定够用**；若真实数据上安全性与覆盖率无法同时达标，小 CNN 应作为单独提案评估。

**为什么不能只写手工最终阈值：** “有上下页边的真跨页”和“同样布局的普通双页”可能拥有完全相同的留白统计。任何模型都无法恢复扫描时已丢失的信息，困难样例必须允许拒判。

## 2. 问题定义与非目标

### 2.1 要保护的是阅读内容，不是扫描外观

输入是一张已按阅读方向解释、宽大于高的静态图片。语义标签：

- `SPREAD`：在候选分界处切开会破坏有意义的跨页构图。包括“上方一个跨页大格，下方普通分格”等混合布局。
- `TWO_PAGES`：左右是可独立阅读的页面，切分不会截断重要的跨页内容。
- `AMBIGUOUS`：即使人工观察输入也无法可靠区分，例如宽缝丢失了关键画面。训练时不强行归入某个二分类标签；用来评价拒判行为。

运行时 `UNKNOWN` 还包括不支持的输入、低质量、资源限制或模型缺失，必须附原因，不能作为语义 `SPREAD` 的成功计数。

### 2.2 第一阶段不做

- 不做画面修复、补画、拼接、OCR、目标检测或漫画语义理解。
- 不做全景拼接式重叠图像配准：左右通常没有重叠内容。
- 不做任意非刚性形变、每个区域独立寻找错位、无限分辨率升级。
- 不改变原图，不为了识别而生成并保存新的 JPEG。
- 不在运行时下载/训练模型，不上传漫画页，不增加原生 ML 运行库。
- 不支持动画逐帧分类；不将彩页/封面强行纳入未经验证的黑白页模型。
- 不自动学习某章节的预测标签，更不将“上一页预测成双页”作为下一页的事实。

## 4. 输出契约与决策优先级

建议新增纯数据接口，名称可在实现时按工程规范调整：

```kotlin
enum class ContentClass { SPREAD, TWO_PAGES, UNKNOWN }
enum class CutSafety { CENTER_SAFE, OFF_CENTER, UNRESOLVED }

data class SpreadAnalysis(
    val contentClass: ContentClass,
    val calibratedSpreadScore: Float?, // 仅模型与校准适用时存在
    val cutSafety: CutSafety,
    val seamLeftFraction: Float?,
    val seamRightFraction: Float?,
    val reason: AnalysisReason,
    val detectorVersion: Int,
    val modelVersion: String?,
)
```

`calibratedSpreadScore` 是在指定验证分布上的分数校准结果，不是开放世界正确率保证。调试特征不随每个缓存条目常驻。

运行时处理顺序：

1. 当前内容版本的用户覆盖规则优先；本方案不要求新增 UI，但接口要容纳它。
2. “分割双页”关闭：不运行检测、不切分。
3. “跳过大跨页”关闭：保留已有强制分割行为，不运行本检测器。
4. 增强开关关闭：走现有 legacy，不改变旧行为。
5. 增强开关打开、首版 veto-only：legacy 判“不切”时直接沿用其判定，**不运行**新阶段（因此目标②的召回上限不变）；legacy 判“可切”时进入新阶段。这个顺序与当前代码一致，明确保留为兼容边界。
6. 只有 `TWO_PAGES && CENTER_SAFE` 自动切分；`SPREAD` 保留；`UNKNOWN/OFF_CENTER/UNRESOLVED` 在支持域内默认保留但记录原因；**模型缺失、域外格式、运行失败则回退步骤 5 之前的当前完整路径**，不得变成“一律不切”。
7. 是否允许新阶段把 legacy 的“不切”改成“切”（突破召回上限），是单独的目标②提案：需要更高置信度、`CENTER_SAFE` 全满足，并对比当前已发布路径独立报告新增切分与新增误切。**未证实之前不启用。**

“未知保留”是偏向避免破坏构图的产品策略，不算识别成功，必须与普通双页漏切率一起评价。未训练或未通过发布验证的分类器只能用于 shadow/offline 实验，不能把全 UNKNOWN 的原型当成增强功能交付。

## 5. 输入规范、解码与资源上限

### 5.1 坐标约定

分析图坐标原点左上，`x ∈ [0,W)`、`y ∈ [0,H)`；区间均左闭右开。输入宽图 `W0 > H0`，长边归一化到至多 512，不放大小图：

```text
W = min(W0, 512)
H = max(1, floor(H0 * W / W0))
```

灰度、mask 和几何坐标必须对应同一张、同一朝向的分析图。不能一阶段在约 768 宽、另一阶段在 512 宽比较阈值。这里的方向是解码/文件方向，不依赖切分后才运行的阅读器自动转正，否则会形成“先识别才能旋转、先旋转才能识别”的循环。

第一阶段有效域的初始建议：`W >= 256`、`H >= 128`、`1 < W/H <= 2.5`。超出有效域返回 `UNKNOWN/UNSUPPORTED_GEOMETRY`，而不是从大幅截断/极端长图推出跨页结论。该域需用样本验证，避免无谓排除正常扫描。

### 5.2 解码路径

- 从已有图像 bounds/元数据取得尺寸，不能为每个 stage 重复读 bounds。
- 若已有**可安全共享且尺寸已合适**的软件位图，可直接分析；不为了复用而读回硬件位图或持有完整巨图。
- 否则独立 peek/source 工厂，先用二次幂 `inSampleSize` 采样，再精确缩小到分析尺寸。
- 二次幂选择：最大 `s=2^k` 使 `W0/s >= 512`；源图不足 512 则 `s=1`。所有尺寸运算使用 Long 并检查溢出。
- 分析图上只保留 ARGB_8888 或等效确定格式；透明输入先与确定的浅底合成，不能把透明像素隐含 RGB 当成黑缝。
- 格式/decoder 无法遵守有界采样时，不采用“先完整解码再缩小”的兜底；返回 UNKNOWN。大图 decoder 原生内存必须另外实测。
- 图片读取、方向处理、抽样规则与版本都属于测试契约；EXIF 或 decoder 自动旋转不可被重复应用。第一阶段应与现有阅读器实际展示方向一致。
- bitmap 所有权显式化；`normalize` 也必须在 try/finally 覆盖内。只回收本次独占创建的对象。

## 6. 特征提取算法

### 6.1 一次生成共享灰度和梯度

逐行取 ARGB，用现有 BT.601 整数式：

```text
Y = (299R + 587G + 114B) / 1000
```

保留原始 `Y`，另生成纸色校正图 `J`；黑缝、阴影和颜色质量信息必须能回看原始值，不能完全依赖归一化结果。

纸色估计的原型规范：

1. 左右半图分别按 32×32 网格统计灰度直方图，边缘不足一个 tile 时使用实际像素数。
2. `P90` 使用直方图的 nearest-rank 第 `ceil(0.9*n)` 个值。每半图另计算一个全局 `P90_half`。
3. tile 的候选纸色 `B_tile = clamp(P90_tile, P90_half-48, P90_half+32)`，再限制到 `[32,255]`。
4. 在各半图内对 tile 中心值双线性插值得到缓慢变化的 `B(x,y)`，边缘用最近中心值延拓；不跨中央混合两个半图的纸色。
5. `J(x,y) = clamp(Y(x,y) + 240 - B(x,y), 0, 255)`。

此处理只减少低频亮度差，不保证消除装订阴影。大面积深色画面也可能被误当纸色，因此同时保留原始对比度和归一化改变量；低信息/过强校正要进入质量判断，不是“修好了”。

在 `J` 上计算 Sobel `Gx/Gy`（signed short），`M=abs(Gx)+abs(Gy)`（unsigned range，用 short/Int 解读）。计算四方向非极大值抑制；梯度方向用比较/查表量化，不对每个像素调用 atan2。

初始边缘门槛：`Tedge = clamp(P75(M over all pixels), 48, 160)`。只在需要时计算端点的浮点方向。图像无足够边缘时不人为制造门槛以下的“内容”。

强墨迹 mask 初始为 `J < 180`。它只是特征，不是浅色线条不存在的证明。扫描外缘的脏边不直接等同内容边界。

### 6.2 接缝候选：最多三个，不要求纯白

在中央 `x ∈ [0.44W, 0.56W]` 找候选。把高度分成 8 个等高区带，对每列、每区带计算：

```text
light = fraction(Y >= 220)
dark  = fraction(Y <= 35)
flat  = fraction(abs(Y - median(Y_in_column_band)) <= 12)
edge  = fraction(M >= Tedge)
q_j(x) = max(light, dark, flat) * (1 - edge)
q(x) = median_j(q_j(x))
```

上述中位数/比例用 256-bin 灰度 histogram 计算，不能每列建立大量对象或做通用排序。空区带跳过并标记质量不足。

- 对 `q(x)` 做三列均值平滑；选至多两个局部极大值，`q>=0.75`，相距至少 `round(0.02W)`；同分优先靠近图像中心。
- 在每个区带从 seed 向两边扩展 `q_j >= 0.65` 的连续列，最大总宽度 `round(0.08W)`；seed 本身不达标的区带记为缺测。
- 至少四个区带有测量才构成有缝候选；取区带边界的并集 `[a,b)` 作为保守遮挡带，同时保留区带中心漂移和缺测比例。
- 扩展触及宽度上限的候选标记 `censored`，不得将截断宽度当真实缝宽。
- 始终加入中心零宽候选 `[W/2,W/2)`，用于没有空白缝的连续画面分析。它不提供“这里可安全切分”的证据。
- 去重后候选总数最多三个。没有浅色缝、出现黑缝均不是立即切分的理由。

候选过程可能把空白天空或对话框当成缝，因此 `q` 只是候选可靠性，不是类别得分。宽缝表示缺失信息变多；不能直接给 TWO_PAGES 加决定性分数。

### 6.3 布局特征：鲁棒页边，而非最外一行决定全部

每个候选在遮挡带外各取宽 `round(0.08W)` 的邻接条带，并在左右外缘各取同宽条带。区间为空时该特征缺测。

- 行墨迹率：条带中 `J<180` 的比例。
- 行是背景候选的初始条件：墨迹率 `<=0.05` 且中位 `J>=200`；不能仅以颜色判整张图的类别。
- 顶/底扫描时，先允许排除不超过 `round(0.01H)` 的连续外缘污染行，再找连续背景段。
- 背景段内允许总量不超过 `round(0.005H)` 的孤立污染行；连续污染两行即结束。排除外缘污染行本身不计入页边宽度。
- 超过污染预算时记录质量不足，不能任意向内搜索直到找到想要的页边。
- 上下边各自最多统计到 `0.25H`，防止空白页/大天空被解释为特别强的页边。

这样可容忍少量扫描黑边和散点，但仍承认“空白天空”和真实页边有时无法区分。页边仅作弱特征。

其他布局描述：

先在细化强边缘图上建立隐式 8 邻接图。链从度数不等于 2 的像素出发，沿未访问边走到下一个分叉/端点；纯闭环从坐标字典序最小点起步，固定邻居访问顺序。每条边只访问一次，链的最小二乘方向和长度用于下面的框线描述。分叉导致长框线被拆短是已知弱点，不通过任意连接分叉来“修正”；必须用格框样例评估。

- `outerMarginL/R`：从外侧向内按相同墨迹率原则估计，最多 `0.15W`；外缘污染预算换成 `0.01W`。
- `frameLikeL/R`：在对应半图中，长水平/垂直边缘链（长度 >= 该半图相应边长的 0.25，且离轴角 <= 5°）所占的强边缘像素比例，限制到 `[0,1]`。只表示框线倾向，不宣称完成格框检测。
- `periodicity`：8 区带边缘密度序列在非零 lag 1..3 的最大归一化自相关，取正部分；方差为零时记 0 并标记低信息。它只能给出重复性提示，不能证明两页独立。

### 6.4 内容延续：先做无模型的廉价版本（修订 C）

**修订 C 把本节降级为实验顺序，而不是首版实现。** 原稿直接设计了完整 Sobel/NMS/细化/链追踪和 39 个几何假设；两份审查都指出它的成本远高于尚未证明的增益，且 `framePenalty` 属于手调补丁。以下保留原始规格供后续参考，但首版只实现上一段那个探针级的测量。

#### 6.4.0 已在 #18 实现的探针

见 [#18 的 `tools/spread-probe/README.md`](https://github.com/KiriKira/mihon/blob/experiment/spread-continuity-probe/tools/spread-probe/README.md) 与 [`SpreadContinuityProbe.kt`](https://github.com/KiriKira/mihon/blob/experiment/spread-continuity-probe/core/common/src/main/kotlin/tachiyomi/core/common/util/system/SpreadContinuityProbe.kt)。它只做：固定支持区间的整型全局偏移搜索、相邻条带的行亮度 profile 与行内水平总变差 profile、相关系数曲线、竞争峰差、边界标记、四区带一致性。它没有分类输出、不自动找缝、不接线到阅读器。已知局限（水平框框骗过亮度相关；不同图案可共享同一 profile）已写成测试。

#### 6.4.1 只有当消融证明增益时才实现以下完整规格

对每个候选，在 `a` 左侧和 `b` 右侧留出 2 像素 guard，再在各 8 像素宽的 rail 内提取细化边缘链。

端点提取规则：

1. 从靠近缝的边缘像素向远离缝的方向跟踪 8 邻接边缘，最多 24 步；遇到歧义分叉或折返停止，不能任意选择最能匹配另一侧的分支。
2. 轨迹至少 6 个有效点、横向跨度至少 4 像素，使用最小二乘拟合 `y=m*x+c`；残差 RMS > 2 像素或 `abs(m)>4` 则不作为可靠可跨缝线段。
3. 接缝附近的 `(x,y)` 为端点，保存斜率 `m`、平均梯度强度、线性拟合残差和所属高度区带。
4. 同一边缘双线/近邻端点若高度差 <= 3 像素、方向接近，合为一项，避免一条粗笔画贡献多份独立证据。
5. 每侧 8 区带，每区带最多 4 项，共最多 32 项。按强度×线性度排序，固定 tie-break；不能只保留整页最强的框线。
6. 与上一节长轴向框线链重合的端点降权；不能全删水平线，因为地平线也可能是真内容。

首版不尝试曲线外推、透视恢复或非刚性变换。宽缺损和弯曲轮廓使此证据变弱时，交给融合和拒判，不能通过扩大搜索无限补救。

#### 全局几何假设

右半映射到左半坐标：

```text
yR' = s*(yR - H/2) + H/2 + delta
mR' = s*mR
s ∈ {0.98, 1.00, 1.02}
delta = k * d, k ∈ {-6,...,6}
d = min(2, H/150)             // 浮点像素；共 39 个假设
```

所有区带使用同一个 `(s,delta)`。不允许每个匹配点独立移动；不提供旋转/透视假设。超出范围的错位/倾斜可能只能 UNKNOWN，这是明确能力边界。

#### 单对线段得分

令 `D=xR-xL`，两侧线段分别外推到另一侧：

```text
e1 = abs(yL + mL*D - yR')
e2 = abs(yR' - mR'*D - yL)
e  = (e1+e2)/2
sigma = min(8, 2 + 0.2*D)
position = max(0, 1 - e/sigma)
```

方向单位向量都朝 x 正方向：`u=(1,m)/sqrt(1+m*m)`。使用 dot product，不做角度相减的 wrap 处理：

```text
direction = clamp((dot(uL,uR') - cos(30°)) / (1-cos(30°)), 0, 1)
linearity = max(0, 1 - RMS/2)
strength  = clamp(meanGradient/(2*Tedge), 0, 1)
qEndpoint = linearity * strength * framePenalty
pairScore = position * direction * sqrt(qEndpointL*qEndpointR)
```

`framePenalty` 初始为长轴向框线链端点 0.25，其余 1.0。此值必须通过框线难负例验证，不能凭单个样例调高。

每个几何假设按 pairScore 递减做一对一贪心匹配，初始只接受 `pairScore>=0.4`；同分按坐标排序。同一个端点不能贡献多次。明确采用有界近似匹配而非最优二部图匹配，避免不必要复杂度；在测试中检查贪心误差是否影响决策。

```text
C(s,delta) = sum(accepted pairScores) / max(nLeft,nRight,1)
Cbest = max over 39 hypotheses
prominence = Cbest - median(C over 39 hypotheses)
coverage = supportedHeightBands / 8
```

额外记录有效匹配数、最佳位移、各区带支持差异，以及 `gapReliability=max(0,1-(b-a)/32)`。缝宽 >= 32 分析像素时，几何延续证据可靠性置零，不据此反推 TWO_PAGES。

**重要限制：** 39 次搜索得到的最高分会有“找到了就算”的选择偏差。训练/校准必须运行完全相同的搜索过程；框线、网点和同画风相邻页必须是难负例。一个匹配、一个最佳位移或一个低残差，均不能独立决定 SPREAD。

此外，改进版审查提出的“把 39 个假设的最高分与循环移位零分布比较、要求 z>=3”**不作为已证实的修正**：漫画纵向结构（页眉、天空、格框密度）不平稳，循环移位可能制造过易的对照，且多重取最大不保证近似正态。可以作为实验之一，但必须用真实难负例检验误报，不能写成保证。

## 7. 融合、校准与安全切分

### 7.1 极小模型

每个候选使用同一逻辑回归：

```text
z_i = clip((f_i-mu_i)/max(std_i,epsilon), -6, 6)
logit_c = b + sum(w_i*z_i)
```

`epsilon=1e-6`；valid flag 同样按固定 schema 标准化。先在裁剪前保留 OOD 信息，不能将极端特征裁剪后伪装成正常。

每图取 `imageLogit=max(logit_c over candidates)`，即有候选支持跨页时不轻易切分。**校准是在这个图级 max 聚合之后做**，不能把候选级概率直接称为图级校准概率。

使用独立校准集学习 `Pspread=sigmoid(A*imageLogit+B)`，约束 `A>0`。这是分数校准，不提高算法本身的区分能力。采用稳定 sigmoid 实现。

数值参数为 32 个权重、32 个均值、32 个标准差和 `b,A,B`，float32 原始载荷 **396 bytes**。加 schema、训练 provenance、阈值、支持域等元数据，发布资产预算 <=16 KiB。代码体积也必须通过 APK diff 实测，不能把参数大小等同完整功能大小。

### 7.2 离线训练规范

- 只使用人工可判定的 SPREAD / TWO_PAGES 训练分类器。AMBIGUOUS 单独留作拒判评估。
- 目标是带 L2 正则的二元交叉熵；lambda 从预声明网格中按作品分组交叉验证选择，不用测试集调参。
- 同一图片的候选以 `1/candidateCount` 加权，避免候选多的图被重复放大。图级 max 与候选训练目标存在偏差，必须作为消融项检查；若明显失配，改为直接优化图级平滑 max 的损失，而不是偷偷调测试集阈值。
- 可使用类别权重改善训练，但校准集必须反映目标使用分布；不能把加权训练输出直接当概率。
- 原图与所有合成变体必须始终属于同一 split；同一作品/扫描版本和重复页面也不能泄漏到其他 split。
- 训练、校准、阈值选择、最终冻结测试尽量分开；小数据采用分组嵌套验证，不能反复查看最终测试结果后改规则。
- 导出训练样本清单哈希、特征 schema、脚本版本、系数、校准系数和门槛；没有可追溯产物不准发布。

### 7.3 拒判与阈值选择

输入/预算/模型合法性可在昂贵特征前检查；其余质量门槛在提取后检查。缺失可用模型且非显式开发 shadow 模式时，不运行昂贵特征，并**回退相同设置下的当前完整路径**（含当前增强的否决），不白跑新管线也不改变用户现有行为。

注意：把域外输入变成 UNKNOWN 只有在“该输入当前也不会被切开”时才是保守的。若当前路径会切开而新阶段返回 UNKNOWN→保留，这是行为回退，必须走上面的回退规则。

满足以下任一条件时优先 UNKNOWN：

- 不支持的格式、颜色/尺寸域、方向不确定、解码失败、取消或预算不足。首版颜色域门槛初始为：ARGB 取样时 `max(R,G,B)-min(R,G,B)>48` 的像素超过 15%，返回 UNSUPPORTED_COLOR；纸张泛黄也可能被排除，这是须记录的覆盖率损失，不能宣称已经支持所有非白纸色。
- 原型质量门槛：整图原始 `P90-P10<16` 且全部候选的 geometryValid 均为 0；或全部候选同时缺少有效几何和页边；均返回 LOW_INFORMATION。有缝候选全部 censored 且全部 geometryValid=0 时返回 UNRESOLVED_SEAM。上述初始质量门槛必须在稀疏线稿上专门验证。
- 特征明显超出训练支持域。首版可用“至少四个连续特征的裁剪前 abs(z)>6”作为保守 OOD 提示，但它不是真正的 OOD 检测保证。
- 模型缺失、schema/hash 不匹配，或尚未经过图源外验证。

其余情况下：

```text
Pspread <= Tsplit  -> TWO_PAGES 候选
Pspread >= Tkeep   -> SPREAD
otherwise         -> UNKNOWN/AMBIGUOUS_EVIDENCE
```

必须有 `Tsplit<Tkeep`。**概率方向必须写对：`Pspread` 越高表示越像跨页，越不允许切分。** 因此“新增保留”需要足够的跨页证据（高 Pspread），“新增切分”需要更强的独立双页证据（更低的 Pspread）并满足切点安全条件——不是反过来。两者是校准/验证后导出的资产，**本文不指定伪精确的默认概率阈值**。阈值选择优化“不误切跨页”和“足够多普通页能切”的联合曲线，不最大化总体准确率。

若未来允许突破 veto-only 门槛（目标②），切/留必须使用**不对称门槛**，并对比当前已发布路径独立报告“新增切分”和“新增误切”的数量；高门槛只控制风险，不能宣称消除了新增误切。

只要中心零宽候选使图级分数升高，可能增加保留率；这是明确的保守聚合取舍，须与 max/mean/最可信缝候选聚合做消融，不能只报安全性收益。

### 7.4 语义是双页，不代表中心可切

首版 `CENTER_SAFE` 采用以下可执行的保守规则：

1. 至少一个有效、未截断的有缝候选，在 **8 个区带全部** 都有测量且 `[a_j,b_j)` 包含 `xc=floor(W/2)`。不能仅因区带并集跨过中心就宣称可切。零宽候选永远不能满足此条件。
2. 每个区带的原始中心列 `q_j(xc)>=0.65`。这允许白、灰、黑的低纹理分界；没有以 `J>=230` 为前提。
3. 在 `xc-3..xc+3` 的中心走廊中，若存在实际连接走廊左右边界的细化强边缘链，且该链不是长轴向框线，则为 UNRESOLVED。链必须至少 6 个点、横向跨度 >=6、拟合 RMS <=2；这里检查的是实际像素连接，不是 6.4 节跨缺损的虚拟外推。
4. 若中心走廊原始灰度的 Sobel 图也发现上述跨越链，而归一化图没有，仍为 UNRESOLVED；原始 Sobel 仅对窄走廊按相同 Tedge 计算，复用 scratch，不新增整图缓冲。

不满足条件 1 时：如果所有有效缝测量一致偏离中心，记 OFF_CENTER；否则 UNRESOLVED。不满足条件 2..4 记 UNRESOLVED。

这些规则只提供保守几何检查，仍非语义证明，最终只对已判 TWO_PAGES 的图应用。黑色均匀装订线可以是安全分界；跨越走廊的水平格框允许被框线规则排除，但语义模型仍可能把它所在的图判成 SPREAD。

该判据很可能使部分斜缝、无留白拼页进入 UNKNOWN。必须在黑缝、格框交点、普通页接触边缘样例上评价覆盖率；不够时应审查规则，而不是偷偷把“8 区带全部”放宽成容易误切的多数票。

后续如果支持偏心切分，应单独修改 `CutPlan` 和分割实现，使两片完整覆盖原图且不丢失像素。不能只改识别器返回值，继续调用固定 `width/2` 切分。

### 7.5 端到端伪代码

```text
analyze(content, versions, budget):
    validate model/schema and supported input metadata
    if unavailable/unsupported: return fallbackToCurrentPath(reason)
    with owned decode resources and cancellation checks:
        image = boundedDecodeAndNormalize(content)
        Y, J, edges, quality = preprocess(image)
        release exclusively owned image bitmap
        candidates = measuredSeams(Y, edges) + centerZeroWidthCandidate
        candidates = deduplicateAndCap(candidates, 3)
        featureRows = []
        for candidate in candidates:
            check cancellation and soft deadline
            layout = measureLayout(candidate, Y, J, edges)
            endpoints = traceBoundedEndpoints(candidate, edges)   // only if ablation kept it
            matches = search39GlobalHypotheses(endpoints, budget) // only if ablation kept it
            featureRows += encodeFeatures(candidate, layout, matches)
        if quality/support-domain gate fails: return fallbackToCurrentPath(reason)
        imageLogit = max(linearModel(row) for row in featureRows)
        score = calibrateAfterAggregation(imageLogit)
        category = thresholdOrAbstain(score)
        safety = centerCutSafety(candidates, Y, J, edges)
        return scalarResult(category, score, safety, versions)
    finally: release only resources owned by this task
```

软预算取消不返回部分 featureRows；没有候选匹配不等于 TWO_PAGES；并行消费者取消不允许提前释放共享任务仍使用的缓冲。训练和推理需复用相同算法/参数，不能线下使用无限搜索、线上偷偷裁剪。

## 8. 移动端复杂度、内存和功耗预算

### 8.1 静态上界，不等于实测时间

在分析长边 512 下 `N<=262,144`：

- 灰度/归一化、Sobel、mask、行列统计：固定次数 O(N) 扫描；不对每个像素创建 Kotlin 对象。
- 轨迹跟踪每端点最多 24 步，候选/端点数封顶；边缘跟踪使用 visited 标记，避免重复遍历整张图。
- 几何打分上界：`3 candidates × 39 hypotheses × 32 × 32 = 119,808` 个 pair evaluation。
- 贪心匹配排序最多每假设 1,024 对，复用数组；排序开销必须计入 profiling。不能把 pair evaluation 数冒充 CPU 指令数。
- 三个候选的线性分类开销相对图像扫描可忽略，但仍不宣称总耗时。
- 不用 GPU/NPU delegate，不加载新的 native runtime，不持有 wake lock。

### 8.2 已知 buffer 预算

按照最坏 512×512 计算：

| 项目 | 字节数/约束 |
|---|---:|
| ARGB 分析位图 | 1,048,576 |
| 二次幂中间位图 | 理想采样尺寸下 <4,194,304 |
| 缩放瞬间两位图共存 | <5,242,880，不含 decoder opaque 内存 |
| 四张 byte 图（Y/J/ink/edge） | 1,048,576 |
| Gx/Gy 两张 short 图 | 1,048,576 |
| magnitude 一张 short 图 | 524,288 |
| 最坏 Int 工作队列/索引图 | 1,048,576 |
| 每像素 8 方向访问位图（隐式图的边访问状态） | 262,144 |
| 逐行 ARGB scratch | 2,048 |
| 32 维模型原始参数 | 396 |

归一化后立即释放独占中间位图；抽取完灰度后释放独占分析位图。多个 stage 复用 scratch，不能同时保留整图 ARGB IntArray 和位图再重复生成 DoubleArray。

已知 buffer + 必需 bookkeeping 的目标上限 **8 MiB/活跃任务**。这是设计预算，不是 Android decoder RSS 保证；原生 decoder 的 opaque allocation、对象开销和现有阅读器完整位图另测。中间 bitmap 的实际宽高和 allocationByteCount 必须检查，不符合预算时停止分析。

### 8.3 待测性能目标与软预算

首版验收目标（需按设备结果调整，不能当现有性能）：

- 指定中档设备上，预解码灰度后的 CPU 特征分析 p95 <=25 ms；指定低档设备 p95 <=50 ms。
- 含分析解码的端到端 wall time 单列报告，目标中档 p95 <=80 ms；大图/特殊 codec 不承诺此数值，超出时调整支持域。
- 特征阶段设置 50 ms 的合作式 soft deadline；在行循环、候选、假设边界检查取消和截止时间，超时返回 UNKNOWN，不发布半成品分数。
- **native decode 不一定可被协程及时中断。** `withTimeout` 不是硬 CPU/内存限流，也不能在超时后立刻开第二个仍与旧 decode 并行的任务。
- 全局最多一个分析任务持有活跃 decoder/大 scratch。只有实际释放资源后下一个任务才能开始。

耗电通过“减少工作次数和无效预取”控制，不能仅靠一次算法毫秒数：

- 已缓存页重复来回翻动，新增分析次数必须为零。
- 快速滑动时丢弃尚未开始的旧预取；不分析整章，不离线全库扫描。
- 首版只在当前页和下一候选可见页调度；低电量、省电模式、后台或 thermal throttling 时禁止新增预取，当前页按既定策略处理。
- 不为这项功能申请电池优化豁免或新增后台服务。

## 9. 缓存、异步和阅读器接入

### 9.1 服务边界

建议拆为：

- `SpreadAnalyzer`：纯 Kotlin 数组输入，输出特征/判定；无 Android Bitmap、无 IO，便于 JVM 回归。
- `SpreadImageDecoder`：Android 解码/方向/所有权/尺寸预算；只产出有界分析输入。
- `SpreadDecisionService`：缓存、single-flight、优先级、取消、版本校验。
- pager/webtoon adapter：把判定转换为稳定显示计划，不在 view 内复制算法。

这些是建议文件/类边界，不要求为文档阶段创建空实现。

### 9.2 缓存键与生命周期

不能只用 URL、页码或 holder identity 当 key。建议：

```text
ContentKey = sourceId + mangaId + chapterId + pageIndex
           + contentRevision + imageGeometryOrientation
AnalysisKey = ContentKey + detectorVersion + modelHash
            + preprocessVersion
```

- `contentRevision` 优先使用现有下载文件/cache 的 generation/元数据。URL 重签名不应被当成新内容，URL 相同也不代表内容相同。
- 本地文件可用路径身份+长度+mtime，仍承认同长度同 mtime 替换风险；有可靠内容摘要就用。不要为检测额外完整读取/哈希每张巨图。
- 在线内存流没有稳定 revision 时，只在本次 page-loader generation 范围内缓存；重新获取后失效，不做不可靠的持久缓存。
- 算法原始输出不随“是否启用分割”变化；开关改变的是显示计划，不必使正确的内容分析缓存全部失效。
- 首版采用有界内存 LRU（建议最多 512 条标量结果，并设置实际字节预算）。512×192 bytes=98,304 bytes 只是紧凑载荷估算，Java/Kotlin Map/key 对象远不止这些，缓存总目标 <=512 KiB，以实际 retained size 调整。
- 不缓存 bitmap、source、Activity 或 holder。持久缓存留到后续，避免引入数据库迁移和陈旧结果问题。
- UNKNOWN/DECODE_ERROR/BUDGET_EXCEEDED 也按原因缓存到本次内容 generation，避免每次绑定都重试耗电；手动重试、新内容版本或模型升级才重新执行。任务取消不持久化为内容失败。

### 9.3 single-flight 与取消

- 同 AnalysisKey 共享一个任务；消费者有独立订阅/等待，不让一个 holder recycle 取消其他消费者还需要的分析。
- 当前页优先于预取；队列有上限，旧预取可丢弃。取消后台任务是合作式的，不能在 decoder 仍运行时释放其正在使用的输入。
- 结果完成时校验 chapter/content generation 和当前绑定 token，避免旧页结果写入新 holder。
- coroutine scope 由 reader/session 服务持有，不使用 GlobalScope；reader 退出后取消队列，资源通过 finally 收敛。
- 临时 decoder/source 归任务所有，用户当前用于展示的 source 不可被关闭或推进。

### 9.4 不允许“看一半突然变成两页”

每个原始页在进入当前显示 epoch 前获得不可变 `DisplayPlan`：

```text
WHOLE(originalPageId)
SPLIT(originalPageId, firstSide, secondSide)
```

- 缓存命中立即确定计划；未命中只在既有加载阶段等待一次有界分析。
- 若显示等待预算已耗尽，当前 epoch 先按 WHOLE；晚到结果只更新缓存，不在用户当前正在看的页面上自动插入/删除半页。
- 在用户明确改开关、重新进入章节或其他已定义的布局重建边界应用新计划。不要把不可预测的“翻到旁边再翻回来”隐式当重建触发点。
- 显示计划冻结是布局策略，分析任务未完成时不允许无限卡住首屏；decode 的不可中断部分仍遵守单 worker 约束。

### 9.5 InsertPage 派生项重建（修订 C）

**已证实的残留问题已由 #17 用较小改动修复并合并，不再作为重做架构的理由。** 本节保留为"如果将来真的引入缓存/异步判定"时的契约：

1. 原始页列表仍是唯一 source of truth；派生半页按当前设置生成。
2. 设置/计划 epoch 改变时，清理当前页和邻章预处理队列中的派生半页，再按新设置重建，并锚定在同一原始页。
3. 邻章 `preprocessed` 是根据旧设置生成的派生状态，清空本身正确；需要验证的是清理-重建-定位的时序，尤其 RTL、邻章预处理、旧异步任务晚到，而不是笼统地视为"丢数据"。
4. 以稳定 `originalPageId + side` 保存锚点；切回整页时回到原始页，不能直接沿用已经变义的 adapter index。
5. 阅读进度、预加载、书签和章节边界继续按原始页 identity 解释。
6. webtoon 不产生同样的 InsertPage，但也必须使用同一个分析结果与计划冻结规则，不能分别识别得出不同结果。

旧实现的缺陷（`#17` 之前的代码）：增强/跳过开关变化只触发 `imagePropertyChangedListener` → `refreshAdapter()`，不清理已插入的半页，导致"整页 + 旧半页"重复。修复方式是新增设置变化回调、清理当前与邻章派生半页、重建后锚定原页。剩余未验证项：pager 交互未真机测试；跳过的外缘污染行不计入页边宽度，可能使临界样例少测最多 1%H，而判定门槛是 2%H。两种定义（计入/不计入）应在真实临界样例上比较后再定，不能直接认定应加回。

## 10. 数据、回归与发布门槛

### 10.1 样本清单

每张图记录：稳定 sample ID、作品/章节/扫描版本/图源分组、人工标签、可切位置/范围（若有）、困难因素、授权/存储位置。原图不一定提交公开仓库；公开可发布匿名特征和可合法分发的合成测试。

必须覆盖：

- 真跨页：满版、有上下页边、宽白缝/灰缝/黑缝、局部跨页、大片天空、框中跨页。
- 扫描扰动：上下错位、轻微高度缩放/倾斜、渐变阴影、纸色差、JPEG 噪声、污边、页码干扰。
- 普通双页难负例：同作品相邻页、格框同高、同样网点、相似场景、裁去内页边、上下满版。
- 模型域外：彩页/封面、极暗页、极端比例、透明图、不同 decoder 格式与尺寸。

两位标注者独立判断，有分歧进入 AMBIGUOUS 或复核，不能用算法输出来改人工标签。

### 10.2 扰动测试

扰动同时作用在正负两类，且保留相应标签语义：

- 上下偏移分别覆盖搜索范围内、边界、范围外。
- 缝宽从无缝到细缝、宽缝、超过可靠性上限；增加缝时明确是“插入空隙”还是“删除原图内容后填缝”，两者不能混称。
- 缝亮度连续扫过 legacy 的 230 附近，并包含深灰/近黑，验证不会继承原门槛断崖。
- 添加真实感的平滑阴影和少量散点，而不是只用纯色矩形。
- 外缘脏边、上下页边与错位组合；不是每种因素只单独测一次。
- 原图、缩放图、JPEG 重编码图的输出稳定性；不要求所有扰动都必须强行分类，允许由确定降为 UNKNOWN，但不应无理由从 SPREAD 跳成安全切分。

合成变体不是独立样本，不用成千上万个变体制造虚假的统计置信度。

### 10.3 指标

分别报告：

1. 真跨页误切率：实际自动切开的 SPREAD / 所有 SPREAD。
2. 普通双页正确自动切分率：自动切开且切点安全的 TWO_PAGES / 所有 TWO_PAGES。
3. UNKNOWN 比例和具体原因；不能把 UNKNOWN 当 SPREAD 算准确率。
4. 切分输出的正确率，以及错误切点率。
5. 每图源/作品/难例子集的指标；已知域与未见图源分开。
6. 重复绑定 cache hit、真正分析次数、p50/p95 CPU/wall、峰值内存、取消后的残留工作。
7. **纯负类难例子集（如"格框对齐的相邻页"）只报告错误保留率/误报率，不计算 ROC AUC**——没有正类时 AUC 无定义。若需要 AUC，必须加入对应真跨页构成双类别评估集。
8. 单一特征单独看可能接近随机（例如只有格框时），这不证明它与布局特征**组合**后无增益；去留由联合消融决定，而不是单特征 AUC。

初始产品验收目标建议：真跨页误切率的 95% 上界 <=1%，普通双页正确自动切分率的 95% 下界 >=80%。**这是待审查的目标，不是当前可达到的承诺。** 数据不足、分组过少时不得给出虚假窄置信区间。

任何"比当前好多少"的结论必须区分**新增保留**和**新增切分**：允许新增切分会引入新的误切来源，高门槛只降低概率，不消除它；只报总体误切率会掩盖这一点。

统计按作品/扫描分组 bootstrap，并做 leave-source-out 测试；页面相关性很强，不能把每个合成变体当 iid 样本套二项分布。具体样本量依据组数、误差和区间决定，不预先声称“几百张足够”。

### 10.4 Android 性能与能耗实验

- 至少选定一台低档、一台中档 Android 设备，记录 SoC、Android 版本、内存、屏幕刷新率和温度；真实型号在执行前确定。
- 使用固定本地文件集，先单测 feature-only，再测含 decoder 的 detector，最后测完整 reader 流程。
- 跑关闭增强、当前增强、新方案三个条件；相同页面顺序、亮度、刷新率、网络状态、缓存状态；交替/随机顺序以降低温升偏差。
- 覆盖冷 cache、热 cache、正常翻页、快速来回翻页、取消预取、切换设置、章节跳转、后台再返回。
- 使用 Android Benchmark/Perfetto 等采集线程 CPU、wall、分配和卡顿；能取得 power rails 时记录能量，否则明确使用 CPU time 等代理指标，不拿电量百分比短时波动证明省电。
- 不为本方案擅自操作用户手机；设备测试另需授权。文档交付不等于真机验证。
